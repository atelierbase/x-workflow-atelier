# 02-generate: 投稿生成（v3.1 / 海外翻訳 → 「私」口調変換）

このフェーズの目的は、ネタリストから **「ひろ｜AI実業家」スタイルの投稿** を21本作ること。

## 入力

- `~/atlier-base-v1/projects/sns-auto-post/x/storage/stocks/drafts.md` の最新ネタリスト
- もしくはフェーズ①「ネタ仕入れ」の出力を直接

## 出力

投稿候補 21本（朝7・昼7・夜7）。
オーナー承認後、ローカルの `pending.md` に書き込み → git push して GitHub に反映。

## 事前読み込み（必須）

- `references/00-context.md`（世界観・鉄則）
- `templates/voice-guide.md` v3.2（一人称「私」、絵文字1個までOK、ですます調、楽しく前向き）

> 投稿タイプは3種（単発／コメント仕込み／画像付き）。各タイプの書き方とフォーマットは `agents/writer.md` を参照（ルーティンも同じ定義を使う）。
- `templates/single-post-templates.md`（単発の型）

これを読まずに書くと、必ずキャラがブレる。

## ステップ

### Step 1. ネタリストを 21 ポストに展開

ネタ仕入れの 21 トピックを、以下の形式で1本1本展開：

```
日付（YYYY-MM-DD）+ 時間帯（朝/昼/夜）+ 軸（主軸/サブ軸1/サブ軸2）+ ソース + 文面
```

### Step 2. 翻訳 → 「私」口調に変換

**翻訳のコツ**：

1. **直訳しない**（要点抽出）
   - ❌ 「Anthropic announced today that Claude Code now supports background sessions」
   - ◎ 「Claude Code の Background Sessions、最近よく使うようになりました」

2. **専門用語は必ず一文で解説**（中級者ターゲット）
   - ❌ 「MCP tunnels が地味に大きい」
   - ◎ 「MCP tunnels は、社内ネットワークにある MCP サーバーを公開せずにエージェントから使える仕組みです」

3. **出典は本文ではなく、控えめに匂わせる**
   - 「先週、Anthropic が〜を発表しました」
   - 「海外で話題の〜」
   - 「Hacker News で1位になった〜」
   - **URL は投稿本文に貼らない**（ストック内のメタ情報に残す）

4. **「私の体験」とセットにする**
   - 翻訳だけだと「翻訳機」と思われる
   - 必ず最後に「私も〜」「私は〜」を入れる

### Step 3. 軸別のテンプレート構造

#### 主軸（海外翻訳）の基本構造（朝枠中心・10-11本）

```
[時間語]、[誰が][何を]発表しました / 話題になっています。

[ざっくり説明：何の機能か、何の話か]
[専門用語があれば必ず解説]

[私の実体験・感想・所感]
```

例：
```
今週、Anthropic が「Routines for Claude Code」を発表しました。

ざっくり言うと、Claude Code の処理を
ルーティン化して、自動実行できる仕組みです。

これまで人間が毎回プロンプトを書いていた作業を、
あらかじめ「ルーティン」として保存しておく。

私も自分のリポジトリの定期チェックを
ルーティンに移し始めました。
```

#### サブ軸1（自分の実例）の基本構造（昼枠中心・6-7本）

```
[最近 / 最近よく〜] [機能名]、[感想/評価]。

[具体的な使い方の説明 = 1-2文]

[私の体験・数字・所感]
[感情語：「ぐっと楽になりました」「びっくりしました」など]
```

例：
```
Claude Code の Background Sessions、
最近よく使うようになりました。

`claude --bg` で投げて、メインの作業を続ける。
完了したら Agent View で確認するだけ。

長時間タスクを「待つ時間」が、なくなりました。
私は別タスクと並列で進められて、
体感の作業効率が確実に上がっています。
```

#### サブ軸2（実業家視点・思考）の基本構造（夜枠中心・4-5本）

```
[最近の現象・トレンド観察]

[AI実業家として思うこと]

[私の立ち位置・行動]
```

例：
```
今週、AI業界では大型提携の発表が相次ぎました。

・KPMG × Anthropic（276,000人）
・Dell × OpenAI（オンプレ Codex）
・NVIDIA × OpenAI（GPT-5.5 インフラ）

「AIをどこに置くか」が、企業選びの軸になっている感覚。

AI実業家として、自社のサービスを「どの AI 基盤に乗せるか」を
真剣に考えるタイミングが来ていると感じます。
```

### Step 4. 21本の配分チェック

書き終えたら必ず以下を確認：

```
朝（07-09）: 7本 / 主軸 5本 + サブ軸1 1本 + サブ軸2 1本
昼（12-13）: 7本 / 主軸 1本 + サブ軸1 5本 + サブ軸2 1本
夜（19-22）: 7本 / 主軸 4本 + サブ軸1 1本 + サブ軸2 2本

主軸合計: 10-11本（50%前後）
サブ軸1合計: 6-7本（30%前後）
サブ軸2合計: 3-4本（20%前後）
```

### Step 5. pending.md への書き込み

`~/atlier-base-v1/projects/sns-auto-post/x/storage/stocks/pending.md` を**書き換え**（追加でなく全置換も可）：

各エントリのフォーマット：

```markdown
## YYYY-MM-DD-NNN
- 種類: 単発
- 投稿想定時刻: 朝（07:00-09:00） / 昼（12:00-13:00） / 夜（19:00-22:00）
- 想定日: YYYY-MM-DD（曜日）
- 軸: 主軸 / 海外翻訳 ・ サブ軸1 / 自分の実例 ・ サブ軸2 / 実業家視点
- ソース: [どの記事・発表・トピックから]
- 文面:

[全文]

- ステータス: pending

---
```

### Step 6. git push

```bash
cd ~/atlier-base-v1/projects/sns-auto-post/x
```

これで GitHub Actions の次回配信から反映される。

各投稿について：

- [ ] **絵文字は0〜1個**（v3.2。2個以上はNG）
- [ ] **ですます調が崩れていない**（タメ口・体言止め多用NG）
- [ ] **専門用語は一文で解説されている**
- [ ] **「私の実体験」が含まれている**（翻訳機にならない）

- [ ] **過度なびっくりマーク連発（！！）がない**
- [ ] **マウント・煽り表現がない**
- [ ] **「ミライ塾」「アトリエの店主」「うちのアトリエ」など旧キャラ用語が入っていない**
- [ ] **本名「石井」が入っていない**
- [ ] **文字数: 280文字以内**（X仕様の制限）

## よくある失敗パターン（v3.1 改訂時に学んだ）

1. **絵文字を入れすぎてしまう**
   - v3.2 で1個までOK。ただし2個以上は連発感が出る。書き終わって個数を確認
2. **一人称が「ひろ」になってしまう**
   - 表示名は「ひろ」だが、本文では「私」
3. **専門用語の解説を省略してしまう**
   - 「Multiagent Orchestration」「MCP tunnels」など、初出は必ず1文で解説
4. **過去発表の話題を「今週」と書いてしまう**
   - Karpathy 1月発表、GPT-5.5 4月発表 → 「今週」にならない
   - 発表時期を確認してから時間語を選ぶ
5. **翻訳だけで「私」のフックがない**
   - 必ず「私も〜」「私は〜」を入れる
